# DR Music 0.2.0 原生迁移验证

目标环境：Windows x64、MSVC / CMake、系统 WebView2 Evergreen Runtime。0.1.0 的 Electron 验证不能替代当前版本的验证。

自动化入口：

```powershell
.\scripts\build.ps1 -SkipInstall
ctest --test-dir build -C Release --output-on-failure
npm run test:smoke
```

原生测试使用自动生成的 WAV、MP3 帧、FLAC 元数据与图片，以及独立临时目录，覆盖：

- C++ / TagLib 元数据、时长、递归扫描、去重、收藏/歌单/主题/标题栏保存与重新读取。
- 独立元数据测试锁定 TagLib 2.3.2，自动生成 zlib 压缩的 ID3v2.3 标题/封面、中文与多值标签及多张内嵌图片；验证有效正面封面优先、损坏候选跳过、MIME/扩展名错误、外部图片回退、原生缩放后的尺寸和像素、缓存写入失败恢复、封面版本 URL，以及旧索引只迁移一次。
- 同名歌词查找、UTF-16LE 解码、无效 ID、损坏索引备份、移除索引时保留音频。
- 原生缓存测试验证 LRU 字节/条目上限、淘汰后流仍可读取、共享内存流的定位/克隆/Range、相同图片复用解码对象；锁住源音频和歌词文件验证缓存命中不重新打开文件，并检查重启后元数据复用、标签变化、优先封面修复、封面缓存丢失重建、歌词变更/关联与目录移除失效。仅内容哈希封面 URL 允许 immutable 缓存，旧版本 URL 仍校验。
- 导入先返回文件名和可播放路径，显式后台读取后补齐标签/时长；验证中断后待处理任务可恢复、旧任务不能覆盖重新扫描结果或恢复已移除歌曲。
- 移除目录及子目录时批量清理歌曲、收藏、歌单引用与封面，保留名称相近的其他目录、单独导入的歌曲及磁盘音频；使用一万首缓存歌曲和六个歌单验证批量清理与持久化，并注入保存失败验证原状态完整保留。
- Range 解析、非法/越界范围、IStream 有界读取、定位、克隆与长度报告；资源 URL 不接受任意路径。
- 原生 D2D 标题栏命中测试、固定窗口标题、最大化/还原、系统标题栏切换、标题栏按钮提示的 500ms 延迟与禁用状态清理。
- 标题栏鼠标离开事件回归：隐藏窗口后派发离开通知，验证不会反复注册离开通知、形成消息循环并饿死绘制消息。

前端逻辑测试覆盖 LRC 时间轴/翻译/分词、YRC 时间、纯文本歌词、队列循环与随机边界，以及目录批量清理和后台增量合并；验证后台更新保留收藏/设置、不恢复已移除歌曲、不覆盖新一轮扫描。共享提示系统跟随 `../dr-dict` 和 `../dr-reader`：页面按钮、被截断的歌曲信息与原生标题栏按钮均使用同一顶层自绘 popover；动态新增或更新的原生 `title` 会转为 `data-tooltip`，不会出现第二套浏览器提示。页面状态过渡由 Motion 14.12.0 实现，并通过 `MotionConfig` 遵循系统的减少动态效果设置。

桌面测试直接启动 `build/bin/Release/dr-music.exe`，使用显式本机 CDP 端口连接系统 WebView2，不启动 Electron，也不使用模拟的 native bridge。检查文件夹扫描、歌曲播放、Range 读取、收藏和歌单保存、AMLL 点击定位、TTML 渲染、当前歌词流光动画、重新扫描、固定页面标题、网易云风格强调色、自绘提示的延迟显示与关闭、动态 `title` 接管、深浅主题提示、目录移除、新建歌单输入框高度与字体栈，以及主题与原生标题栏切换。数据位于 `.test-data/native-smoke/`，不接触正式音乐库。

设置 `DR_MUSIC_SMOKE_EXE` 可用同一套桌面测试验证分发目录中的原生可执行文件。正常启动不开放 CDP 调试端口。

桌面回归另行检查重新扫描先返回待补齐的歌曲，随后通过原生增量事件完成元数据更新。目录移除测试主动延迟请求并注入一次失败：在原生数据尚未改变时验证界面、播放信息已清空，失败后恢复记录；再次放行真实请求后验证磁盘索引、收藏、歌单引用及播放队列已清理，生成的 WAV 文件保留。

封面桌面回归将生成的 BMP 内容写入 `folder.jpg`，确认原生识别为 PNG 缓存且 WebView2 实际解码成功；模拟一次图片加载失败、修改图片后重新扫描，验证封面版本 URL 改变且图片恢复显示。缓存图片的实际像素变化由原生测试验证。

桌面测试还检查未修改文件时再次扫描保留封面哈希、版本和缓存字节；即使上次图片加载失败，未修改图片的重新扫描也能重新尝试显示。

范围限制：音频实际解码以生成的 WAV 为主；其他编码的所有变体、超大音乐库、多显示器跨 DPI、Snap Layouts 弹出行为与系统媒体键在不同 Windows / Runtime 版本上的表现仍需更多真机覆盖。当前不提供 macOS / Linux 原生宿主，不含额外音频转码器。

原生外观检查曾发现最大化后标题栏重绘被鼠标离开消息循环阻塞，已修复该循环并将 D2D 绘制区域限制为独立标题栏 HWND。修复后的自动化回归可重复运行；本次最终手动外观复查因用户按 Esc 停止桌面自动化而未继续。

原生播放测试使用外部 FFmpeg CLI（仅测试工具）自动生成十种 PCM/压缩音频；验证全部文件解码到有限、非静音的 PCM、完整长度、前后定位、Unicode 路径、损坏/缺失文件。使用 miniaudio 的显式 null 后端验证原生时钟、暂停后位置保持、恢复、音量、播放结束/重播、切歌及旧命令拦截。检查 FFmpeg 构建不含 H.264 解码、AAC 编码、HLS 和网络。桌面测试使用实际默认音频设备，检查原生状态中的进度/时长、暂停保持、非法歌曲 ID 拒绝，以及 AMLL 点击定位和目录移除停止播放。前端测试检查延迟事件不会覆盖新的选曲、定位或停止状态。系统媒体键在不同硬件/Windows 版本上的表现仍需真机覆盖。

播放界面回归检查正常歌词不显示解析类型提示；歌词文件与偏移工具栏默认透明、悬停/键盘聚焦后显示，切换时不移动布局。主界面音量条显示百分比，播放页可展开独立音量控件；实际滚轮事件验证双向 5% 调节、两处值同步、0%/100% 边界、静音恢复和 Escape 收起。
